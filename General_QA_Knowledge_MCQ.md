# General QA Knowledge Assessment - MCQ

## Software Testing Fundamentals

### 1. What is the primary objective of software testing?
- A) To prove that the software has no defects
- B) To find as many defects as possible
- C) To ensure software meets requirements and works as expected
- D) To delay the release date

**Answer: C) To ensure software meets requirements and works as expected**

### 2. Which testing principle states that testing shows the presence of defects, not their absence?
- A) Exhaustive testing is impossible
- B) Defect clustering
- C) Testing shows presence of defects
- D) Pesticide paradox

**Answer: C) Testing shows presence of defects**

### 3. What is the Pesticide Paradox in software testing?
- A) Tests become ineffective over time if not reviewed and updated
- B) Bugs multiply like insects
- C) Testing kills all bugs
- D) More testers means fewer bugs

**Answer: A) Tests become ineffective over time if not reviewed and updated**

### 4. What does the Pareto Principle (80/20 rule) suggest in testing?
- A) 80% of bugs are found in 20% of modules
- B) 80% of tests pass, 20% fail
- C) 80% of testing time, 20% of development time
- D) 80% manual testing, 20% automation

**Answer: A) 80% of bugs are found in 20% of modules**

### 5. What is Early Testing principle?
- A) Testing should start as late as possible
- B) Testing activities should begin early in the SDLC
- C) Only test after deployment
- D) Test only the UI first

**Answer: B) Testing activities should begin early in the SDLC**

## Types of Testing

### 6. What is the difference between Verification and Validation?

- B) Verification: Are we building the product right? Validation: Are we building the right product?
- C) Verification is done by developers only
- D) Validation is not important

**Answer: B) Verification: Are we building the product right? Validation: Are we building the right product?**

### 7. Which type of testing verifies individual components or units?
- A) Integration Testing
- B) System Testing
- C) Unit Testing

**Answer: C) Unit Testing**

### 8. What is Integration Testing?
- A) Testing individual units
- B) Testing the interaction between integrated components
- C) Testing the entire system
- D) Testing by end users

**Answer: B) Testing the interaction between integrated components**

### 9. What is Regression Testing?
- A) Testing new features only
- B) Re-testing to ensure existing functionality still works after changes
- C) Testing performance
- D) Testing security

**Answer: B) Re-testing to ensure existing functionality still works after changes**

### 10. What is Smoke Testing?
- A) Testing in a smoky environment
- B) A quick preliminary test to check basic functionality
- C) Performance testing
- D) Security testing

**Answer: B) A quick preliminary test to check basic functionality**

### 11. What is Sanity Testing?
- A) Testing mental health applications
- B) A narrow and deep testing of specific functionality after changes
- C) Testing everything
- D) Random testing

**Answer: B) A narrow and deep testing of specific functionality after changes**

### 12. What is the difference between Smoke and Sanity testing?
- A) No difference
- B) Smoke is broad & shallow, Sanity is narrow & deep
- C) Smoke is for security, Sanity is for performance

### 13. What is Exploratory Testing?

- C) Testing in different geographical locations

### 14. What is Ad-hoc Testing?

- C) Automated testing
- D) Performance testing

### 15. What is User Acceptance Testing (UAT)?

## Black Box vs White Box Testing

### 21. What is Black Box Testing?
- A) Testing internal code structure
- B) Testing without knowledge of internal implementation
- C) Testing only dark themes
- D) Testing in a dark room

**Answer: B) Testing without knowledge of internal implementation**

### 22. What is White Box Testing?
- A) Testing UI only
- B) Testing with knowledge of internal code structure
- C) Testing only white backgrounds
- D) Testing without documentation

**Answer: B) Testing with knowledge of internal code structure**

### 23. Which technique belongs to Black Box Testing?
- A) Statement Coverage
- B) Branch Coverage
- C) Equivalence Partitioning
- D) Path Coverage

**Answer: C) Equivalence Partitioning**

### 24. Which technique belongs to White Box Testing?
- A) Boundary Value Analysis
- B) Decision Table Testing
- C) Statement Coverage
- D) State Transition Testing

**Answer: C) Statement Coverage**

### 25. What is Gray Box Testing?
- A) Testing only gray colored interfaces
- B) Combination of Black Box and White Box testing

- D) Automated testing only

**Answer: B) Combination of Black Box and White Box testing**

### 26. What is Equivalence Partitioning?

### 27. What is Boundary Value Analysis?

- B) Testing values at the edges of equivalence partitions

### 29. What is Decision Table Testing?

### 30. What is State Transition Testing?
